# VNami — User Flows

> Сценарії роботи людини в редакторі. Функціонал описано в [OVERVIEW.md](OVERVIEW.md), модель даних — у [SCHEMA.md](SCHEMA.md).

## 0. Принципи UX

1. **Дія там, де вона потрібна.** Кнопки з'являються безпосередньо в місці, де можна щось додати або змінити. Шукати їх у меню не доводиться.
2. **Створення на місці.** Новий блок з'являється одразу там, де він стоятиме, як «чернетка», яку треба лише заповнити. Модальних вікон для створення немає.
3. **Мінімум кліків.** Автофокус у потрібному полі, вибір і введення без зайвих вікон.
4. **Дерево росте зліва направо**, бо застосунок працює на широкому екрані комп'ютера. Виходи блоків і варіантів розташовані на правому краї блоку.
5. **Нічого не страшно зламати.** Будь-яку дію можна скасувати (Ctrl/Cmd+Z). Після видалення з'являється сповіщення з кнопкою «Скасувати».
6. **Живе полотно.** Після кожної зміни розкладка плавно (анімовано) перебудовується, а полотно саме прокручується до нового блоку.
7. **Миша насамперед.** Розширені гарячі клавіші й клавіатурна навігація — після MVP. У MVP працюють лише базові клавіші: Enter / Shift+Enter / Esc у полях вводу, Ctrl/Cmd+Z / Shift+Z, Delete, Ctrl/Cmd+C/X/V.

## 1. Анатомія полотна

Відкритий проєкт має три розділи, перемикач між ними — у верхній панелі:
- **Діалоги** — білдер: список сцен і полотно. Тут нічого зайвого, лише робота з діалогом.
- **Персонажі** — окремий розділ зі сторінкою для кожного персонажа (розділ 10).
- **Про проєкт** — назва, опис лору й коротка статистика (розділ 15).

```
 ┌─────────────────────────────────────────────────────────────────────────────┐
 │ Проєкт ▾ │ [Діалоги] Персонажі  Про проєкт │ 🔍  ⚠ 2 │ 🤖 │ Збережено ↶ ↷   │
 ├───────────┬─────────────────────────────────────────────────────────────────┤
 │ СЦЕНИ   + │ Ранок — Дорогою до криниці ГГ зустрічає Бена.                   │
 │ ▸ Ранок   │                                                                 │
 │   Криниця │  ┌───────────────────┐    ┌──────────────────────────┐          │
 │           │  │ ● Бен             │    │ ● ГГ                  ◇  │          │
 │           │  │ Привіт, ГГ! Відра ├───►│ ◇ О, Бене, візьми одне   ├──► …     │
 │           │  │ не надто важкі?…  │    │   відро.                 │          │
 │           │  └───────────────────┘    │ ◇ Дякую, але я сама      ├── (+) ⇥  │
 │           │                           │   впораюся.              │          │
 │           │                           └──────────[+ Варіант]─────┘          │
 │           │                                              [мінікарта]        │
 └───────────┴─────────────────────────────────────────────────────────────────┘
```

- **Ліва панель білдера:** лише сцени.
- **Верхня панель:** проєкт, перемикач розділів, пошук, лічильник проблем, індикатор агента, стан збереження, undo/redo.
- **Полотно:** блоки, зв'язки, кнопки `(+)`, мінікарта, кнопки зуму та «вмістити все».
- Персонажа для блоку вибирають прямо на полотні (розділ 4), тож для роботи з діалогом переходити в розділ «Персонажі» не потрібно.

## 2. Блок на полотні

Блок — це персонаж і його репліки. Окремого типу «блок вибору» немає: блок з однією реплікою — звичайний крок діалогу, з кількома — вибір гравця.

- **Заголовок:** кольорова позначка й ім'я персонажа. Клік по імені відкриває вибір персонажа.
- **Репліки:** кожна репліка — окремий рядок зі **своїм виходом на правому краї блоку**. Одна репліка показується до 4 рядків тексту; у виборі кожен варіант — до 2 рядків з позначкою `◇`. Повний текст видно під час редагування або в підказці при наведенні.
- **Вибір** (кілька реплік) має фіолетову рамку й позначки `◇`, щоб його одразу відрізняли від звичайної репліки.
- **Позначки:** `⚑ старт` на стартовому блоці. Блок із проблемою має червону рамку, а при наведенні на `⚠` видно, що саме не так.
- **Панель дій при наведенні** (маленькі іконки над блоком):
  - `⚑` зробити стартовим;
  - `↶` повернути на авторозкладку (лише в переставленого вручну блоку, розділ 8a);
  - `🗑` видалити.
- **Заголовок** (позначка `⋮⋮`) — ручка перетягування блоку (розділ 8a).

  Згортання гілки й дублювання з'являться пізніше.
- **Кнопка `+ Варіант`** під блоком (при наведенні) додає ще одну репліку — так блок стає вибором.
- **Підказки:** кожна кнопка при наведенні показує підказку одним-кількома словами, що вона робить.
- **Контекстне меню** (правий клік) з тими самими діями — пізніше.

## 3. Виходи та кнопка `(+)`

Кожен **непідключений вихід** (`next = null`) має коротку лінію-«відросток» у стилі зв'язку, а на її кінці кнопку `(+)`.

```
  [ блок ]──────(+) ⇥        звичайна репліка без продовження
  ◇ Варіант ────(+) ⇥        варіант без продовження
  [ блок ]──────[→ Далі: Біля криниці]   перехід на початок іншої сцени
```

- **Клік по `(+)`** («Новий блок») створює новий блок (розділ 4).
- **При наведенні** праворуч від `(+)` з'являється кнопка **«Далі»**. Вона відкриває меню (у ньому ж є «З'єднати з блоком», розділ 8):
  - **перейти на початок сцени** — список інших сцен проєкту;
  - **«+ Нова сцена»** — створює сцену й одразу веде в неї;
  - **«Кінець історії»** — маркер «КІНЕЦЬ».

  Кнопка лишається видимою, поки курсор над `(+)` або над нею, а меню — доки не вибрано пункт (Esc або клік поза меню закриває його).
- **Перехід до сцени** показується на кінці виходу плашкою-посиланням «→ Далі: Назва сцени». Клік відкриває ту сцену, `×` при наведенні прибирає перехід (на виході знову `(+)`). Перехід у порожню сцену — помилка, поки в ній немає стартового блоку.
- У тому ж меню «Далі» є «З'єднати з блоком» — список блоків сцени, з якими можна з'єднати вихід (розділ 8).
- Відросток непідключеного виходу має **червонуватий** відтінок, бо це проблема. Маркер «КІНЕЦЬ» має нейтральний сірий колір.

Маркер «КІНЕЦЬ» прибирається кліком по ньому (підказка «Прибрати кінець»): вихід знову отримує `(+)`.

## 4. Створення блоку (головний сценарій)

1. Користувач натискає `(+)` на виході.
2. Розкладка анімовано звільняє місце, і **на місці майбутнього блоку** з'являється **чернетка** — блок із пунктирною рамкою.
3. У чернетці одразу відкритий **вибір персонажа**:
   - персонажі показані в тому ж порядку, що й у списку персонажів;
   - список фільтрується під час набору: точний збіг і збіг з початку імені йдуть першими; Enter обирає підсвіченого персонажа, а стрілки ↑/↓ переміщують підсвічування;
   - якщо такого імені немає, пункт **«+ Створити персонажа «Ім'я»»** стоїть першим. Персонаж створюється одразу з автоматичним кольором, а поле тексту відкривається без очікування, тож можна одразу друкувати.
4. Після вибору персонажа фокус переходить у **поле репліки**:
   - Enter зберігає блок;
   - Shift+Enter додає новий рядок у текст;
   - Esc скасовує: чернетка зникає, і нічого не створюється.
5. Кнопка **`+ Варіант`** у чернетці додає ще одне поле репліки — блок стане вибором. Enter у будь-якому полі зберігає весь блок; порожні поля пропускаються.
6. Після збереження чернетка стає звичайним блоком, а на кожному вільному виході з'являється власна `(+)`.
7. Кожен збережений блок є окремим кроком undo.

> **Пост-MVP: автопродовження.** Після Enter одразу відкривається наступна чернетка праворуч від щойно створеного блоку, щоб лінійний діалог можна було писати без миші: персонаж, текст, Enter… Esc або Enter на порожньому тексті зупиняє ланцюжок.

**Порожня сцена.** У центрі полотна стоїть велика кнопка `(+) Додати перший блок`. Перший створений блок автоматично стає стартовим.

## 5. Вставка блоку між наявними

- При наведенні на **лінію зв'язку** посередині з'являються `+` («Вставити блок») і `×` («Відключити»).
- `+` відкриває чернетку **між** двома блоками. Розкладка розсуває дерево, а далі все відбувається як у розділі 4. Перша репліка нового блоку отримує старе продовження, тож ланцюжок не рветься.

## 6. Вибір (кілька реплік)

- **Додати варіант:** кнопка `+ Варіант` під будь-яким блоком. З'являється поле: Enter додає репліку й одразу відкриває поле для наступної, Esc або Enter на порожньому полі завершує. Наявні репліки й зв'язки не змінюються.
- **Редагування тексту репліки:** подвійний клік.
- **Порядок варіантів:** перетягування за ручку `⋮⋮` ліворуч від варіанта (пізніше).
- **Видалення варіанта:** іконка `×` при наведенні на репліку (лише коли реплік кілька). Продовження цього варіанта стає «осиротілим» і підсвічується червоним. Остання репліка блоку не видаляється — видаляється сам блок.
- Якщо лишилася одна репліка, блок знову виглядає як звичайна репліка.

## 7. Редагування блоку

- **Текст репліки:** подвійний клік відкриває редагування на місці. Enter або клік поза блоком зберігає зміни, Shift+Enter додає новий рядок, а Esc скасовує зміни.
- **Персонаж:** клік по імені в заголовку відкриває той самий вибір персонажа, що й під час створення.
- Окремої панелі властивостей у MVP немає: все редагується прямо на блоці.

## 8. Зв'язки

- **Створити:**
  - разом з новим блоком — через `(+)` на виході (розділ 4) або вставку на лінії (розділ 5);
  - з **наявним блоком** — перетягнути від точки виходу (кружечок праворуч від репліки) і відпустити будь-де на блоці; під час перетягування блоки, з якими можна з'єднати, підсвічуються блакитним. Або меню «Далі» біля `(+)` → «З'єднати з блоком» (список блоків сцени).
  - Відпустити перетягування на порожньому місці — створити там новий блок (розділ 4).
- **Видалити:** навести на зв'язок і натиснути `×` («Відключити»). Вихід знову отримує `(+)`.
- **Сходження** (кілька зв'язків в один блок) — звичайні лінії, як і всі інші зв'язки; блок показується один раз.
- **Цикли** (зв'язок назад у блок вище по гілці або в той самий блок, наприклад повернення до меню питань) дозволені. Така лінія йде справа наліво, тож малюється пунктиром поверх блоків, щоб її було видно й можна було відключити.
- **Після MVP:** перепідключення кінця наявної лінії перетягуванням.

## 8a. Розташування блоків

- Блоки розкладаються **автоматично** (зліва направо, без накладань). Автоматика не завжди ставить блок так, як зручно людині: наприклад, довгий зв'язок може пройти під іншими блоками.
- **Переставити вручну:** заголовок блоку — ручка перетягування (позначка `⋮⋮` зліва, курсор-«рука»). Тягнути можна за будь-яке місце заголовка, крім імені персонажа (клік по ньому змінює персонажа). Блок їде за мишею разом зі своїми `(+)`, «Кінцем» і плашками переходу. Якщо виділено кілька блоків, вони їдуть разом. Репліки за перетягування не відповідають, щоб не заважати виділенню й редагуванню тексту.
- Переставлений блок **лишається там, де його поставили**, і позиція зберігається в проєкті (поле `pos`, [SCHEMA.md](SCHEMA.md)). Решта блоків і далі розкладаються автоматично. Перетягування — одна дія, її можна скасувати.
- **Повернути на місце:** кнопка `↶` у панелі дій переставленого блоку. Кнопка «Авторозкладка» під кнопками зуму (видно, лише коли в сцені є переставлені блоки) повертає на авторозкладку всі блоки сцени.
- Копії блоків (вставка, дублювання сцени) з'являються в авторозкладці.

## 9. Виділення, копіювання, видалення

- **Виділення:** клік по блоку. Shift/Ctrl+клік додає блок до виділення, рамка мишею виділяє кілька блоків.
- **Видалення людиною:** `🗑` або Delete. **Без діалогу підтвердження:** з'являється сповіщення «Видалено 3 блоки · Скасувати». Зв'язки, що вели у видалені блоки, стають червоними `(+)`.
- **Копіювання:** Ctrl/Cmd+C/X/V, або дублювання через `⧉`. Вставлена копія отримує нові ID і з'являється як окрема гілка, яку можна під'єднати до потрібного виходу. Копіювати можна й між сценами.

## 10. Персонажі

Окремий розділ «Персонажі», щоб не займати місце біля полотна.

- **Ліворуч список:** кольорова позначка, ім'я й кількість реплік. Кнопка `+` створює персонажа з автоматичним кольором і одразу відкриває його сторінку.
- **Праворуч сторінка вибраного персонажа:**
  - колір (палітра + довільний колір) та ім'я;
  - опис та історія — велике поле;
  - стиль мовлення — з підказкою, що агент дотримується його, коли пише репліки;
  - сцени, де персонаж говорить, з кількістю реплік. Клік по сцені відкриває її в білдері;
  - кнопка видалення.
- Зміни зберігаються одразу, як і всюди.
- **Видалення:**
  - якщо персонаж не має реплік, видаляється одразу, зі сповіщенням «Скасувати»;
  - якщо має, з'являється **діалог підтвердження**: «У Олі 14 реплік. Вони залишаться без персонажа й будуть позначені червоним». Діалог тут доречний, бо зміна зачіпає багато місць;
  - для «Автора» кнопки видалення немає.
- **Створення з білдера:** у виборі персонажа на полотні є «+ Створити персонажа» (розділ 4). Він створює персонажа лише з іменем; решту полів заповнюють пізніше в цьому розділі.

## 11. Сцени

- **Список** у лівій панелі. Клік відкриває сцену, поточна сцена підсвічена.
- **`+ сцена`** створює новий рядок з активним полем назви й одразу відкриває сцену з кнопкою «Додати перший блок».
- **Подвійний клік** по назві дозволяє її перейменувати.
- **Опис сцени** видно під назвою у верхній частині полотна, а клік по ньому дозволяє редагувати. Якщо опису немає, на цьому місці стоїть сірий напис «Додати опис…».
- **Порядок сцен** змінюється перетягуванням у списку.
- **Контекстне меню:** перейменувати, дублювати, видалити. Видалення непорожньої сцени запитує підтвердження.
- **Стартовий блок:** `⚑` у панелі дій блоку.

## 12. Проблеми

- Блок або вихід із проблемою має червону рамку або червоний відросток. Так позначаються **всі незавершені місця**: блок без персонажа (наприклад, після видалення персонажа: текст лишається, поле персонажа порожнє), порожній текст, непідключений вихід, недосяжний блок.
- **Поки в проєкті є помилки, експорт заблоковано.** Кнопка «Експорт» неактивна, а підказка на ній показує кількість помилок і відкриває їхній список. Попередження (наприклад, «лише один варіант») експорт не блокують.
- Збереження від помилок **не залежить**: стан проєкту зберігається завжди (розділ 15).
- **Лічильник `⚠ N`** у верхній панелі відкриває список проблем поточної сцени, а перемикач — усього проєкту. Клік по проблемі переводить полотно до неї й підсвічує місце.
- Кількість проблем видно також біля кожної сцени в списку сцен.

## 13. Навігація

- **Панорама:** перетягування фону або прокрутка трекпадом.
- **Зум:** колесо з Ctrl/Cmd або щипок на трекпаді. Також є кнопки `−` / `+` і кнопка `⤢ вмістити все`.
- **Мінікарта** в куті полотна. Клік по ній переводить огляд у відповідне місце.
- **Згортання гілок:** `▾` на блоці.
- **Пошук:** поле у верхній панелі. Збіги підсвічуються, Enter переходить до наступного збігу, а поруч видно лічильник «3 з 12». Можна шукати в поточній сцені або в усьому проєкті.

## 14. Робота разом з агентом

- **Індикатор `🤖` у верхній панелі:** сірий означає, що агент не підключений; зелений — що підключений; пульсує, коли агент щойно щось змінив.
- **Зміни агента** підсвічуються на полотні: нові або змінені блоки світяться кілька секунд. Якщо зміна поза екраном, з'являється сповіщення «Агент додав 5 блоків · Показати».
- Полотно **не стрибає саме** до змін агента, щоб не заважати людині. Перейти до них можна кнопкою «Показати».
- **Запит на видалення від агента** з'являється як панель поверх полотна, але не блокує роботу:
  - видно, що агент хоче видалити й причину (`reason`);
  - блоки, які буде видалено, підсвічуються, а стрілки, що зникнуть, показані пунктиром;
  - кнопки «Підтвердити» / «Відхилити» і таймер, скільки лишилося часу на відповідь.
- Якщо людина саме редагує блок, який змінює агент, то зміна агента застосовується після того, як людина збереже або скасує своє редагування. Текст, який людина набирає, не перезаписується.

## 15. Проєкти

Проєкт — це набір сцен (і персонажів, що в них говорять) із **назвою** та **довгим описом лору**. Застосунок сам зберігає всі проєкти у своєму сховищі, тож шукати файли на диску не потрібно.

- **Перший запуск:** екран «Проєкти» з великою кнопкою «Створити проєкт».
- **Екран «Проєкти»:** список карток із назвою, початком опису лору, кількістю сцен і датою останньої зміни. Звідси проєкти створюють, відкривають, перейменовують, дублюють і видаляють. Видалення потребує підтвердження.
- **Перемикання між проєктами:** назва проєкту ліворуч у верхній панелі є випадним меню. У ньому список проєктів для швидкого переходу, пункт «+ Новий проєкт» і пункт «Усі проєкти…», що відкриває екран «Проєкти». Перемикання миттєве, бо поточний проєкт уже збережено автоматично.
- **Новий проєкт:** користувач вводить лише назву. Проєкт створюється з персонажем «Автор» і порожньою сценою «Сцена 1», яка одразу відкривається.
- **Розділ «Про проєкт»:** окремий розділ (не панель біля полотна) з назвою, великим полем для опису лору й короткою статистикою: кількість сцен, персонажів, реплік і помилок. Агент теж читає опис лору як контекст.
- При запуску застосунок відкриває останній проєкт, з яким працювали.
- **Автозбереження** працює постійно у фоні: якщо є незбережені зміни, вони записуються **щосекунди**. Кнопки «Зберегти» немає. У верхній панелі видно стан «Збережено» / «Зберігається…».
- **Експорт JSON:** меню проєкту. Доступний лише тоді, коли в проєкті немає помилок (розділ 12). Результат — файл в окремому, версіонованому форматі експорту (див. [SCHEMA.md](SCHEMA.md)).
- **Імпорт JSON:** на екрані «Проєкти». Створює новий проєкт із файлу експорту.
- **Оновлення застосунку:** проєкти, збережені старішою версією, автоматично оновлюються до нового формату під час відкриття. Перед цим застосунок робить резервну копію.

## 16. Ухвалені рішення

| Питання | Рішення |
|---|---|
| Орієнтація дерева | Зліва направо |
| Підказка мовця в чернетці | Не потрібна в MVP |
| Видалення людиною | Блоки — без підтвердження, зі «Скасувати»; персонаж з репліками й непорожня сцена — з підтвердженням |
| Блоки видаленого персонажа | Лишаються з порожнім персонажем і підсвічуються червоним |
| Експорт | Заблокований, поки в проєкті є помилки |
| Автозбереження | Щосекунди у фоні, якщо є зміни |
| Автопродовження після Enter | Пост-MVP |
| Проєкти | Кілька проєктів у сховищі застосунку, швидке перемикання; проєкт має назву й опис лору |
